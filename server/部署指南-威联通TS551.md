# 百宝格 NAS 备份服务部署指南（威联通 TS-551 / Container Station）

本指南基于实际部署过程整理，记录了所有踩坑点及对应处理方式。
服务端文件位于项目 `server/` 目录：

```
server/
├── Dockerfile          # 镜像构建文件（已配置国内镜像源）
├── app.py              # Flask 备份服务（4 个接口）
├── requirements.txt    # Python 依赖
└── docker-compose.yml  # Container Station 应用编排
```

---

## 一、部署架构

- 手机与 NAS 连接同一路由器下的家庭 WiFi
- Flask 服务运行在 Docker 容器内，监听容器内 **5000** 端口
- NAS 宿主机因系统 apache-dav 占用 5000，对外映射为 **5050**
- 备份文件存放在 NAS：`/share/Container/baobaoge/backup`
- 资源限制（在 Container Station GUI 配置）：内存 256M、CPU 0.5 核

---

## 二、准备目录与上传文件

1. File Station 中创建两个目录：
   - `/share/Container/baobaoge/server`（存放部署文件）
   - `/share/Container/baobaoge/backup`（存放备份包，自动保留最近 20 份）
2. 将本地 `server/` 目录下 **4 个文件全部**上传到 `.../server/` 目录。
   - 必须连同 `Dockerfile` 一起上传，只传 yml 会导致构建失败。

> 物理路径提示：File Station 中的 `/share/Container` 在 SSH 下实际路径通常为
> `/share/CACHEDEV1_DATA/Container`（TS-551 单卷默认）。

---

## 三、启用 SSH

1. QTS 桌面 → **控制台 → 网络与文件服务 → Telnet/SSH** → 勾选「启用 SSH 服务器」（默认端口 22）→ 应用。
2. Windows 打开 PowerShell 连接（**IP 中间不能有空格**，使用 admin 账户）：

   ```powershell
   ssh admin@192.168.1.11
   ```

   - 首次连接提示 `yes/no` 时输入 `yes`。
   - 输入密码时屏幕不显示字符，属正常现象。
   - 登录成功出现 `[~] #` 提示符。

> 注意：必须用 `admin` 登录执行 docker 命令。自建账户（如 ydy）会报
> `mkdir .../homes/xxx: permission denied`，因为它没有 Container Station 管理权限。

---

## 四、在 NAS 上构建本地镜像（关键步骤）

Container Station「创建应用程序」只复制 yml 文件，**不会携带 Dockerfile 构建上下文**，
因此不能在 compose 里用 `build: .`，必须先 SSH 手动构建镜像，再让 compose 引用本地镜像。

```bash
cd /share/CACHEDEV1_DATA/Container/baobaoge/server
ls -l          # 确认 4 个文件都在，Dockerfile 不能是 0 字节
sudo docker build -t baibaoge-backup:latest .
```

- 命令末尾的点 `.` 不能省略，表示当前目录为构建上下文。
- Dockerfile 已配置国内加速源，无需梯子：
  - 基础镜像：`docker.m.daocloud.io/library/python:3.8-slim`
  - pip 源：清华 TUNA
- 成功标志：`Successfully tagged baibaoge-backup:latest`
- 验证镜像存在：

  ```bash
  docker images baibaoge-backup
  ```

### 若基础镜像拉取超时

按顺序尝试更换基础镜像源，编辑 Dockerfile 第 2 行后重新 `docker build`：

```dockerfile
# 备选 1：阿里云
FROM registry.cn-hangzhou.aliyuncs.com/library/python:3.8-slim
# 备选 2：dockerproxy
FROM dockerproxy.net/library/python:3.8-slim
```

可用 sed 快速替换：

```bash
sed -i 's|docker.m.daocloud.io/library/python|registry.cn-hangzhou.aliyuncs.com/library/python|' Dockerfile
docker build -t baibaoge-backup:latest .
```

> 只有修改了 `app.py`、`requirements.txt`、`Dockerfile` 时才需要重新构建镜像；
> 仅修改端口、卷映射等 compose 配置无需重建。

## 五、导入 Container Station 应用

当前 `docker-compose.yml` 内容：

```yaml
services:
  baibaoge-backup:
    image: baibaoge-backup:latest
    container_name: baibaoge-backup
    ports:
      - "5050:5000"
    volumes:
      - /share/Container/baobaoge/backup:/backup
    environment:
      - TZ=Asia/Shanghai
    restart: unless-stopped
```

操作：Container Station → 应用程序 → 创建 → 导入此 yml 文件。

已处理的兼容性问题：

1. **资源限制字段**：QNAP 不接受 compose 中的 `mem_limit` / `cpus`，
   已从文件中移除；请在「高级设置 → 资源」中手动配置 **内存 256M、CPU 0.5 核**。
2. **version 字段**：Docker Compose v2 中 `version` 已废弃，已删除以消除警告。
3. **build 字段**：已改为 `image: baibaoge-backup:latest`，直接使用第四步构建的本地镜像，
   避免 Container Station 去 docker.io 在线拉取（国内会超时）。
4. **5000 端口冲突**：QNAP 系统服务 `apache-dav` 占用宿主机 5000
   （`netstat -tlnp | grep :5000` 可见），故宿主机映射改用 **5050**。

## 六、验证服务

浏览器（手机或电脑，与 NAS 同网）访问：

```
http://192.168.1.11:5050/health
```

返回类似内容即部署成功：

```json
{"status":"ok","backup_dir":"/backup","max_backups":20}
```

常用排查命令：

```bash
docker ps                                   # 容器是否 Up
docker logs baibaoge-backup                 # 查看服务日志
docker ps -a --filter "publish=5050"        # 查端口映射容器
netstat -tlnp | grep :5050                  # 查宿主机端口监听
```

## 七、APP 端配置

百宝格 APP → 我的 → 同步管理：

| 配置项 | 值 |
| --- | --- |
| NAS IP 地址 | `192.168.1.11`（以实际 NAS IP 为准） |
| 端口 | `5050` |
| 家庭 WiFi SSID 白名单 | 家里 WiFi 名称，多个用英文逗号分隔 |

点「测试连接」提示连接成功即完成。随后可：

- **立即同步**：将本地数据库 + 照片打包为 `bbg_backup_{毫秒时间戳}.zip` 上传 NAS
- **从 NAS 恢复最新备份**：下载、MD5 校验后覆盖本地数据并重启应用
- **查看同步日志**：每次同步的时间、类型（自动/手动）、结果、失败原因
- 自动同步每日凌晨 3 点执行，仅在连接白名单 WiFi 时触发，移动网络下不执行

## 八、日常维护

| 操作 | 命令 / 方式 |
| --- | --- |
| 更新服务代码 | 重新上传文件 → `docker build -t baibaoge-backup:latest .` → Container Station 重建应用 |
| 查看备份文件 | File Station 进入 `/share/Container/baobaoge/backup` |
| 手动查最新备份 | 浏览器访问 `http://NAS_IP:5050/latest-version` |
| 手动下载备份 | `http://NAS_IP:5050/download` |
| 服务接口 | `/health`、`/latest-version`、`/upload`、`/download` |

服务端自带保护机制：上传时校验 MD5，不一致立即删除并返回 400；备份自动保留最近 20 份，超出滚动删除最早版本。
